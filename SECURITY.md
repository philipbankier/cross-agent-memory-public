# Security

Report suspected vulnerabilities privately through this repository's Security > Advisories >
Report a vulnerability control. Confirm that the form is private before entering details. Do not
put vulnerability details, histories or credentials in a public issue. If the private form is
unavailable, do not post sensitive details elsewhere; ask the maintainer for a private channel.

Include the installed revision, operating system, affected command or client, impact and a small
reproduction using synthetic data. Do not send database files, conversation exports, raw logs,
tokens, recovery keys or signed download links. Redact personal paths and account identifiers.

Security maintenance is best effort. No support period or response deadline is promised. Preserve
original histories and recovery material, and review updates before applying them.

This is a single-owner memory system, not an isolation boundary between mutually untrusted people
sharing one OS account. Use a separate instance and credentials for each owner. Keep the node's
MCP origin on loopback behind the approved authenticated transport; never expose a bare port.

Encrypted remote evidence does not encrypt the live index. Restrict node access and use host disk
encryption. Exact-evidence reads can be partial; assistant answers can still misinterpret evidence.
Consequential claims need source, speaker, date and completeness checks. Importing a snapshot does
not establish current provider coverage, and deleting indexed records does not erase old backups.
